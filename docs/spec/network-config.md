# Network configuration

The signer binds itself to one network at startup (`--network`, required, no default). From that binding come the
genesis fork version (for every domain and for the `fork_info` check), the GVR, the genesis time and slot timing (for
the clock bounds and the RANDAO window), and the preset (for the contribution bitvector length).

## Where these facts come from

- The YAML format and key names are those qrysm writes with its `ConfigToYaml` function, and those of the public
  `theQRL/go-qrl-metadata` `config.yml` files. Key names and values are used as **data**: the loader is written from
  this note, not from qrysm's GPL loader.
- The values of the networks qrysm defines in code (fork versions, slot timing, presets) were read from qrysm's GPL
  `config/params` package at `cyyber/qrysm` `0b9cdf25`. They are recorded here as facts. The embedded
  network files are generated by `tools/vectorgen` from that commit (`params.ConfigToYaml`), CI fails on any
  difference, and the signer's tests check the loaded values against `testdata/vectors/networks.json`.
- The `genesis.ssz` prefix layout follows from the `BeaconState` field order of the Ethereum consensus
  specifications, tag `v1.5.0` (CC0-1.0, **[CS]** `specs/phase0/beacon-chain.md`), and was confirmed against a real
  `genesis.ssz` (§4); it is not taken from qrysm's GPL `beacon_state.proto`.

## 1. Keys the signer reads

| Key | Type | Use |
|---|---|---|
| `PRESET_BASE` | `mainnet` or `minimal` | preset values for every key the file does not set (§2) |
| `CONFIG_NAME` | string | reported in `capabilities.network.config_name`; a file without it is named `devnet`, as qrysm names such files |
| `GENESIS_FORK_VERSION` | `0x` + 8 hex | domains and the `fork_info` check |
| `SECONDS_PER_SLOT` | integer | clock bounds, RANDAO window, `capabilities` |
| `SLOTS_PER_EPOCH` | integer | epochs of slots, clock bounds, the RANDAO bucket refill, `capabilities` |
| `SYNC_COMMITTEE_SIZE`, `SYNC_COMMITTEE_SUBNET_COUNT` | integers | contribution bitvector length `SIZE / SUBNET_COUNT` bits; `subcommittee_index < SUBNET_COUNT` |

Loader rules:
- Values the file does not set are inherited from the preset named by `PRESET_BASE` (§2).
- Unknown keys are ignored, so legacy and other clients' keys parse.
- Duplicate keys are allowed and the **last** one wins. qrysm's e2e component writes `DEPOSIT_CONTRACT_ADDRESS` twice,
  and a strict YAML decoder rejects duplicate mapping keys, so the loader walks the YAML node tree itself.
- Domain types are protocol constants ([signing-roots.md](signing-roots.md)) and are not read from the file.
- Networks are never identified by fork version: Testnet V1, Testnet V2 and the old betanet all use `0x20000089`.

## 2. Presets and named networks

Defaults per `PRESET_BASE` (the values of qrysm's `mainnet` and `minimal` configurations):

| Preset | `SLOTS_PER_EPOCH` | `SECONDS_PER_SLOT` | `SYNC_COMMITTEE_SIZE` | `SYNC_COMMITTEE_SUBNET_COUNT` | Contribution bits | `MAX_VALIDATORS_PER_COMMITTEE` |
|---|---|---|---|---|---|---|
| `mainnet` | 128 | 60 | 128 | 1 | 128 (16 bytes) | 32 |
| `minimal` | 8 | 6 | 16 | 1 | 16 (2 bytes) | 32 |

Named networks embedded in the binary (`--network=<name>`):

| Name | `CONFIG_NAME` | `GENESIS_FORK_VERSION` | `PRESET_BASE` | `SECONDS_PER_SLOT` / `SLOTS_PER_EPOCH` | Genesis time and GVR |
|---|---|---|---|---|---|
| `minimal` | `minimal` | `0x00000001` | minimal | 6 / 8 | none (spec-test configuration) |
| `end-to-end` (alias `e2e`) | `end-to-end` | `0x000000fd` | minimal | 10 / 6 | set at run time by the test: pass `--network-genesis-time`; GVR by flag, genesis state or TOFU |
| `end-to-end-mainnet` | `end-to-end-mainnet` | `0x000000fe` | mainnet | 6 / 128 | set at run time, as above |
| `interop` | `interop` | `0x000000eb` | mainnet | 60 / 128 | none |

Not embedded:
- **mainnet** (`0x00000000`, mainnet preset, 60 / 128): QRL has no published mainnet genesis yet, and a placeholder
  would either refuse to start or never sign. It is added by name only when its genesis time and GVR are published.
- **Testnet V3**, the network this signer targets: added by name once its configuration, genesis time and GVR are
  published. Until then, use a file.
- **Testnet V2** (live since 2026-04-01, `0x20000089`) is unsupported: it runs an older stack with 20-byte
  addresses, a 4-byte signing context and signature-based RANDAO, so no signature this signer makes is valid there.

File networks (`--network=<path>`) are the normal case for devnets and for the qrysm e2e, which writes its
configuration with `ConfigToYaml` to `<TestPath>/web3signer-testnet/config.yaml`.

## 3. Genesis validators root and genesis time

Neither value is in the network YAML.

| Value | Sources, in precedence order |
|---|---|
| GVR | named network (compiled in) → `--network-genesis-validators-root` → `--network-genesis-state` (bytes 8-40) → trust on first use |
| Genesis time | named network → `--network-genesis-time` → `--network-genesis-state` (bytes 0-8) |

- **Sources must agree.** When two sources give the same value, startup is refused if they differ: a named network
  against either flag, and either flag against `--network-genesis-state`. A genesis state whose fork bytes do not
  carry the network's `GENESIS_FORK_VERSION` is refused too. Each conflict is a distinct startup error.
- **Trust on first use (TOFU) for the GVR.** Allowed only for file networks, with a WARN, and on non-loopback
  listeners only with `--Xallow-gvr-tofu`; never for named public networks. The first accepted request with a valid
  fork version pins its GVR into the slashing-protection store, and every later request must match.
  `capabilities.network.genesis_validators_root` is `null` until the pin is set. The qrysm e2e uses TOFU on loopback.
- **Unknown genesis time.** Signing clock bounds are off (startup WARN), new RANDAO layers are refused, and
  `capabilities` reports `randao_reveal: false` and `genesis_time: null`. On a non-loopback listener the signer
  refuses to start unless `--Xallow-unknown-genesis-time` is set.
- Startup logs the network name, fork version, GVR (or "pending pin"), genesis time, slot timing, and the DEPOSIT and
  APPLICATION_BUILDER domains.

## 4. `genesis.ssz` prefix

The SSZ serialisation of a container places its fixed-size fields inline, in declaration order. The first four
fields of `BeaconState` in the consensus specification ([CS] phase0 `BeaconState`) are fixed-size, so their bytes sit
at fixed offsets at the start of every `genesis.ssz`, whatever follows:

| Bytes | Field | Encoding |
|---|---|---|
| 0-8 | `genesis_time` | uint64, little-endian (Unix seconds) |
| 8-40 | `genesis_validators_root` | 32 bytes |
| 40-48 | `slot` | uint64, little-endian (0 at genesis) |
| 48-52 | `fork.previous_version` | 4 bytes |
| 52-56 | `fork.current_version` | 4 bytes |
| 56-64 | `fork.epoch` | uint64, little-endian |

The loader reads only these 64 bytes. At genesis both fork versions equal the network's `GENESIS_FORK_VERSION`.
Confirmed on the public Testnet V2 `genesis.ssz`: bytes 0-8 decode to 1775003316 (2026-04-01T00:28:36Z) and bytes
8-40 to the published GVR `0xfbcc79d4…8781`.
